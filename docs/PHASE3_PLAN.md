## 実現可否・API利用方針についての重要な前提

**■2(YouTube Data API直接利用)について、事実確認が必要です。**

現在の動画取得は、このリポジトリに含まれない外部バックエンド(`https://sf6dna-backend.onrender.com`)経由で行われており、YouTube Data APIキーを直接扱う仕組みはフロントエンド側にはありません。そのため、

- 「新しい順」「評価順」のソートや「約10件/15件」といった件数指定が可能かどうかは、**バックエンド側の仕様次第**であり、このリポジトリの変更だけでは確約できません
- 対応方針としては、①バックエンド側のAPI仕様(パラメータ)を確認いただく、②現状のAPIで返る範囲で最大件数を要求し、取得できた分だけ表示する実装に留める、のいずれかになります
- 今回は②(現状のAPIをそのまま使い、`max`パラメータを増やして呼び出す)を前提に計画します。バックエンド側の対応が必要な場合は、その旨を都度明記します

**■7(大会情報のAPI自動取得)も同様です。** 大会情報を配信する外部APIとの契約・仕様は把握していないため、**JSON手動更新方式**を前提とし、将来API化する場合に差し替えやすいデータ構造で設計します。

## 初心者卒業ゲージの設計(新規)

診断・動画視聴・図鑑閲覧・練習など、サイト内の行動を「初心者卒業」に向けた進捗として可視化する仕組みです。

### データ構造(案)

```
sf6dna_graduation = {
    diagnosisDone: true,
    videosWatched: 3,      // 学習履歴から算出
    charactersViewed: 2,   // 学習履歴から算出
    trainingCompleted: 0
}
```

### 進捗率の算出方法

固定の「達成条件リスト」に対する達成数の割合で算出します(例: 診断完了/動画3本視聴/キャラ5体閲覧/練習1回、の4条件のうち何個満たしたか)。**条件は今後増減できるよう、配列で管理**します。

### 既存資産との接続

- 「見た動画」「見たキャラ」は、■学習履歴機能(下記)があれば自動的にカウントできます
- 「診断完了」「練習完了」は既存の`sf6dna_score`・`sf6dna_training_progress`をそのまま参照でき、新規データ収集は不要です

## 保守性・拡張性についての方針

- ランキング・大会情報は、値をハードコードせず**専用のデータファイル(JSライクなJSON)に分離**し、将来API化する際にデータ取得部分だけを差し替えられる構成にします
- 初心者モードによる表示順の出し分けは、各一覧ページの**ソート関数を1箇所に集約**し、将来「表示順の基準」が増えても1箇所の修正で対応できるようにします
- 学習履歴・お気に入りは、キーの命名規則(`sf6dna_history_*` / `sf6dna_favorite_*`)を統一し、今後種類が増えても迷わず追加できるようにします
