# Ver.1.0 Weekend Device QA — 2026-09-30

対象日は2026-10-03〜04（日本時間）。最終Batch PreviewのSHAを記録してから開始する。日付より品質を優先する。Productionへの反映は別承認。

## 実行前

- iPhone Safari、可能ならPC Chromeで実施。OS/ブラウザ版、縦横、表示倍率、端末、Preview SHA、時刻を記録する。
- 通常モードを基本とし、既存端末のlocalStorageは一括削除しない。ゲストと既存テストアカウントを分ける。
- 新規アカウント作成・管理者付与・DB修正をQAに含めない。認証情報はレポートへ書かない。
- このBatchの自動試験はDB_WRITE=NO。利用者が行う実保存とは別の証跡にする。

## 最優先：認証と保存

1. ゲストでAuthを開き、ログイン前の画面を確認する。
2. 既存テストアカウントでログイン。メール表示、遷移先、戻る操作を確認する。
3. 診断を完了する。現行仕様では診断完了時にアカウントへ自動保存するため、追加の保存ボタンがあるとは扱わない。
4. 保存済み表示、Historyの該当結果・回答・時刻を記録する。
5. 結果画面を2回再読込する。同じ完了済み回答から履歴が増えないことを確認する。
6. 通信失敗が実際に起きた場合は保存再試行で同じ結果が1件だけ残ることを確認する。ネットワーク遮断の試験は別枠で実施する。
7. Historyを再読込し、結果が残ることを確認する。
8. 診断を明示リセットして新しく回答する。新しい試行は別結果として保存できることを確認する。
9. ログアウトし、Authがゲスト表示へ戻ること、アカウントHistoryに他人の結果が表示されないことを確認する。端末履歴・FavoritesはlocalStorage由来なので、ログアウト後の残存をアカウント情報漏えいと混同しない。

実保存PASSはブラウザ上の表示だけでなく、同じアカウントのHistory件数と再読込後の状態を照合する。模擬RPC試験を実保存PASSとしない。
