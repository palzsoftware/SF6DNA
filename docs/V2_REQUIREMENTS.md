# SF6DNA v2 要件定義（確定版・要約）

## 1. サービス定義
SF6DNAは、Street Fighter 6をプレイするすべてのプレイヤーを対象とした総合プラットフォームとする。

対象は初心者・中級者・上級者・プロを含む。

最終目標は「SF6で困ったらSF6DNA」と思ってもらえるサービスにすること。

## 2. 4大メインコンテンツ
1. 診断
2. キャラクター情報
3. プレイヤー情報
4. AIコーチング

将来的にAIコーチングへリプレイコーチング機能を追加する。

## 3. 診断方針
診断はサイト全体の入口の1つとして扱い、100問前後の長大な診断を中心にはしない。

原則として短時間で完了できる少数問形式とし、目安は以下とする。

- キャラクター適性診断: 10〜15問程度
- プレイスタイル診断: 10〜15問程度
- 上達・課題診断: 15〜20問程度
- 総合簡易診断: 20問前後

診断結果は簡略化しすぎず、キャラクター辞典・練習・攻略・プレイヤー情報・将来のAIコーチへ接続する。

## 4. キャラクター情報
SF6DNA最大の情報資産とする。

各キャラクターについて、少なくとも以下を体系的に扱える構造を目指す。

- キャラクター概要
- 長所・短所
- 操作難易度
- 得意距離
- 基本方針
- 距離別立ち回り
- プレイ中に考えること
- 通常技
- 特殊技
- 必殺技
- SA
- フレームデータ
- Classic / Modernコマンド
- コンボ
- 確定反撃
- 起き攻め
- セットプレイ
- 対空
- 防御
- ゲージ管理
- バーンアウト
- 画面端
- 技対策
- 連携対策
- キャラ別対策
- トレーニング設定
- 関連動画
- 参考プレイヤー

## 5. プレイヤー情報
対象はプロだけに限定しない。

- プロ選手
- 非プロ強豪
- Legend上位
- キャラ職人
- VTuber
- ストリーマー
- 攻略投稿者
- コーチ
- 海外プレイヤー

プレイヤー情報はキャラクター・大会・試合・動画と関連付ける。

## 6. AIコーチ
初回リリース後の大型機能として扱う。

AI自身に攻略情報を自由生成させるのではなく、SF6DNA内の信頼できる構造化データを検索・参照し、その内容を会話形式で案内する方式を基本とする。

将来はリプレイデータや映像を分析し、被弾要因・対空・ラッシュ対応・確反・ゲージ管理などを解析して改善メニューへ接続するリプレイコーチングを検討する。

## 7. 検索
横断検索を中核機能とする。

検索対象例:
- キャラクター
- 技
- コンボ
- セットプレイ
- 連携
- 対策
- トレーニング
- プレイヤー
- 大会
- 試合
- 動画
- 用語

表記揺れを正式に扱う。

例:
- 弱P
- 弱パンチ
- 小P
- コパ
- 5弱P
- 立ち弱P

内部では正式エンティティIDへ関連付ける。

## 8. データ設計原則
コンテンツはコードではなくデータとして管理する。

主要エンティティ候補:
- User
- Character
- Move
- MoveAlias
- Combo
- Setup
- Sequence
- Counter
- Training
- Player
- Tournament
- Match
- Video
- Glossary
- Patch
- Source
- Diagnosis
- DiagnosisQuestion
- DiagnosisResult

名称をキーにせず内部IDと表示名を分離する。

文字列タグだけに依存せず、関連はIDで管理する。

## 9. パッチ・出典
データには必要に応じて以下を保持できるようにする。

- 対応バージョン
- 有効開始パッチ
- 有効終了パッチ
- 最終更新日
- 出典
- 検証方法

客観データとSF6DNA独自攻略・評価を内部的に区別する。

## 10. UI / UX
- スマホファースト
- 情報量が多くてもシンプルに見せる
- ホームは特に簡潔
- 欲しい情報へ短い導線で到達できることを優先
- 大量画像・動画は遅延読み込み
- SEOを重視し、個別URLを持たせる

## 11. 初期収益モデル
基本無料 + 広告。

主要操作を妨げる広告配置は避ける。

## 12. 開発原則
- 本要件を新しい正とする
- 旧仕様へ新機能を無秩序に継ぎ足さない
- 既存資産は「そのまま再利用 / 修正して再利用 / 再構築 / 廃止 / 新規」に分類する
- mainを直接改修せず、v2開発ブランチで段階的に作業する
- 大規模変更は小さく分割する
- データ基盤を優先して整備する
- AIより先に信頼できる知識DBを作る
