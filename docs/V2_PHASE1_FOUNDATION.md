# SF6DNA v2 Phase 1: 安全な開発基盤

## 目的
SF6DNA v2の本実装に入る前に、現行公開版を壊さず、安全に再構築できる開発基盤を作る。

## Phase 1で行うこと

### 1. main保護
- `main`は現行版の基準ブランチとして扱う。
- v2開発は`sf6dna-v2`ブランチで行う。
- 原則としてv2作業をmainへ直接コミットしない。

### 2. 要件の正本化
- 新要件は`docs/V2_REQUIREMENTS.md`を基準とする。
- 旧README、PROJECT_STATUS、FEATURES等と矛盾する場合、新v2開発ではV2_REQUIREMENTSを優先する。

### 3. 既存資産の分類
既存実装は次の5分類で扱う。

- A: そのまま再利用
- B: 修正して再利用
- C: 再構築
- D: 廃止候補
- E: 新規作成

現時点の代表分類:

| 項目 | 分類 | 方針 |
|---|---|---|
| 診断UI・進捗表示 | B | 少数問診断へ転用 |
| 旧70問前後の診断内容 | C | 短時間診断へ再設計 |
| キャラクター一覧・詳細UI | B | 辞典型構造へ拡張 |
| 静的キャラクターデータ | B/C | 検証後に新データ層へ移行 |
| プレイヤー表示 | B | DB型へ拡張 |
| YouTube API連携 | B | 動画DBと統合 |
| localStorage | B | ゲスト一時保存用途へ限定 |
| 静的JSへの大規模データ直書き | D | DB中心へ移行 |
| 本格リレーショナルDB | E | 新規設計 |
| 管理画面 | E | 新規設計 |
| 横断検索・Alias検索 | E | 新規設計 |
| Patch / Source管理 | E | 新規設計 |
| AIコーチ | B/E | 既存試作を調査し再設計 |

### 4. Backend方針
`SF6DNA-Backend`にはルート側とネスト側の実装が存在するため、Phase 2で正規Backendを1つに決める。

Phase 1では削除・統合を行わず、両方を保全する。

### 5. 変更管理
大規模な一括書き換えは禁止する。

原則:
1. 変更前に対象と影響範囲を確認
2. 小さい単位でコミット
3. 既存公開版を壊さない
4. 破壊的変更は後続Phaseで実施
5. データ移行前に移行元を保持

## Phase 1で行わないこと
- 既存ページの大規模削除
- レガシーファイルの即時削除
- Backendの片方を推測で削除
- 新DB技術の確定
- フレームワーク移行の確定
- AIコーチの本実装
- mainへのv2コード反映

## Phase 1完了条件
- フロント・Backend双方にv2開発ブランチが存在する
- v2要件の正本がリポジトリに保存されている
- 既存資産の再利用方針が文書化されている
- mainを直接変更せず次Phaseへ進める状態になっている
