# PHASE3_FINAL_REVIEW.md

SF6DNA Phase3完了時点での、プロダクトデザイナー兼UXデザイナー視点によるレビューです。実装は行わず、レビューと改善提案のみをまとめています。

---

## ■総合評価

Phase1〜3を通じて、「診断ツール」から「初心者を主役にしたポータルサイト」への構造転換は概ね達成できています。一方で、**「毎日開く理由」がまだホームページの一部の演出に依存しており、コンテンツの継続的な更新性(鮮度)という点では発展途上**です。デザインシステムの一貫性は高く保たれており、保守性への配慮(データ駆動設計、命名規則の統一)は全体を通じて意識されています。

---

## ■初心者レビュー

- **5秒以内に理解できるか**: ホームのヒーロー+「初心者はこちら」ボタン、Beginner GuideのSTEP1〜4カードにより、**初回訪問者の最初の行動は明確**です
- **専門用語**: 「ドライブゲージ」「フレーム」等の対戦格闘ゲーム特有の用語がFAQ以外の場所(診断の質問文、キャラクター詳細等)で無説明のまま使われている可能性があります(要個別確認)
- **導線**: 診断→結果→練習メニューの主導線は明確ですが、**キャラクター図鑑・プレイヤー図鑑からBeginner Guideへ「戻る」導線が無く**、一度そちらに進むと最初の道筋を見失いやすい構造です
- **「戻る」の多発**: ヘッダーのTOPリンクは常時あるものの、**パンくずリストが無い**ため、階層が深いページ(character.html等)から「自分が今どこにいるか」を視覚的に把握しづらい

## ■中級者レビュー

MR1500〜1800のプレイヤーにとって、現状最も価値があるのは「練習メニュー」と「対戦動画」ですが、以下が不足しています。

- **対キャラ対策情報の体系化**: character.htmlに「対策キャラ」表示はあるが、具体的な対策の中身(何が有利/不利か)が薄い可能性があります
- **フレームデータ**: 中級者が最も求める情報の1つですが未実装です(Phase3計画時点でも「今後」扱い)
- **自分の対戦履歴との紐付け**: 現状、ランク管理(MR記録)は手動入力のみで、対戦内容の振り返りとは接続されていません

## ■上級者レビュー

MR1800以上のプレイヤーが継続利用する動機は、現状のサイトには**ほぼ用意されていません**。

- ランキング・大会情報は「準備中」が中心
- コンボ検索・詳細フレームデータなど、上級者が実際に検索する情報が無い
- 上級者向けの分析(自分の対戦データを分析する機能)は「AIリプレイ分析」として構想はあるが未着手

**上級者は現状のSF6DNAを「初心者向けサイト」と認識し、離脱する可能性が高い**と考えられます。

## ■UIレビュー

- **統一感**: Design System(クリップ形状・カラートークン)は概ね守られていますが、**古いページ(players.html/character.htmlの一部)はPhase1以前の角丸カードデザインのまま**で、Phase3で新設したページ(ranking.html/tournament.html/beginner-guide.html)とビジュアルトーンに差があります
- **カードデザイン**: 新設ページはクリップ形状+トークンベース、既存ページ(player.css等)は独自の角丸・グラデーションベースで、**サイト内に2つのデザイン言語が混在している状態**です
- **視線誘導**: ホームは概ね良好ですが、players.htmlは「ピックアップ行3つ→検索→一覧」という縦の情報量が多く、スクロールしないと一覧にたどり着けません

## ■モバイルレビュー

- ヘッダー・ハンバーガーメニューはPhase3-Aで修正済みで、タップ領域も44px基準を満たしています
- **横スクロールの発生**: `.home-marquee`は意図した横スクロールですが、それ以外の箇所(テーブル・グリッド)で意図しない横あふれが発生していないかは、実機確認ができておらず未検証です
- **ページの長さ**: players.htmlは「ピックアップ3行+検索+一覧」で縦に非常に長く、スマホでは「知りたい選手にたどり着くまでのスクロール量」が大きい状態です

## ■アクセシビリティレビュー

- **alt属性**: 動的生成される`<img>`タグを確認した結果、**alt属性の欠落は検出されませんでした**(良好)
- **aria-label**: サイト全体で47箇所使用されており、主要な操作要素はカバーされています
- **フォーカス管理**: Phase3-Aで追加したモーダル・チュートリアルはフォーカストラップ対応済みですが、**それ以前から存在するページ(診断・比較等)のモーダル的なUIには同様の対応が入っていない可能性**があります
- **コントラスト・スクリーンリーダー対応**: 実際のコントラスト比測定・スクリーンリーダーでの通読確認は、この環境では実施できていません

## ■保守性レビュー

- **重複コード**: 動画カードのレンダリングロジックが`characters.js`・`beginner-guide.js`・`home.js`の複数ファイルに個別実装されています。**video-search.jsのような「動画カード生成の共通関数」を切り出す余地があります**
- **軸ラベル辞書の重複**: `home.js`と`training.js`に同じ8軸の日本語ラベル辞書が別々に定義されています(以前から指摘済み、未解消)
- **CSS構造**: `components-v2.css`が肥大化しており(3000行超)、Phase3で追加したCSSも同ファイルへの追記が中心になっています。**Phase4での分割整理が必要**です
- **命名規則**: JSファイルはケバブケースで統一されており良好です

## ■コンテンツレビュー

| コンテンツ | 評価 |
|---|---|
| キャラクター図鑑 | 動画・難易度は充実。**対策キャラの具体的な中身が薄い**可能性がある(要確認) |
| プレイヤー図鑑 | ピックアップ導線が充実。ただし人気順・MR帯別など要望にあった軸は実データ不足で一部未実装 |
| FAQ | 初心者向けは充実。**中級者・上級者向けのFAQが無い**(例: 「MRが伸び悩んでいる」等) |
| Beginner Guide | STEP形式で明快。ただし**一度読み終えた後に再訪する理由が無い**(一度きりのコンテンツ) |
| 大会情報 | サンプルデータのみで、実質「準備中」に近い |
| ランキング | プレイヤー実績のみ実データ。他は「準備中」 |

**優先順位が低いと考える内容**: 大会情報の細かいフィールド拡張(賞金・配信URL等)は、実データが1件も無い現状では**時期尚早**でした。データが入る目処が立つまで、UIの充実より「どうやって実データを継続的に得るか」の検討を優先すべきです。

## ■毎日使いたくなるサイトになっているか

**現状は「初回体験は良いが、2回目以降の理由が弱い」状態**です。

- ホームの「今日のあなたへ」「実績バッジ」は継続動機として機能しています
- 一方、**キャラクター図鑑・プレイヤー図鑑・ランキング・大会情報は「昨日と今日で中身が変わらない」静的なコンテンツ**であり、2回目の訪問で新しい発見がありません
- Beginner Guideも一度見れば十分な内容で、リピート訪問の動機にならない設計です

「毎日開きたくなる」ためには、**ホーム以外のページにも「今日」という時間軸を持ち込む**必要があります。

## ■改善提案(優先度別)

### 優先度: 高

1. **デザイン言語の統一(UIレビューで指摘)**: 新設ページと既存ページのビジュアルトーンの差は、サイト全体の完成度評価に直結します。**理由**: ユーザーはページ間を行き来する際に「同じサイトだろうか」という違和感を無意識に感じ、信頼感を損ないます。**効果**: 統一により、サイト全体の「作り込まれている感」が向上します
2. **動画カード生成の共通関数化(保守性)**: 3ファイルに分散した重複ロジックを1つの共通関数にまとめる。**理由**: 現状、動画カードの見た目を1つ変えるだけで3ファイルを個別に修正する必要があり、修正漏れのリスクが高い。**効果**: 保守コストの削減、将来のAPI仕様変更への対応が1箇所で済む
3. **上級者向けコンテンツの最低限の充実**: フレームデータまでは難しくても、**既存の選手データ(achievements)を使った「大会実績カレンダー」的な見せ方**など、今あるデータで上級者の興味を引く工夫。**理由**: 現状上級者の離脱リスクが最も高い。**効果**: MR1800以上のユーザーの定着率向上

### 優先度: 中

4. **パンくずリストの追加**: 「戻る」の多発を防ぐ。**理由**: 現状ページ間の階層関係が視覚化されていない。**効果**: 初心者の「迷子感」を軽減
5. **中級者・上級者向けFAQの追加**: 「MRが伸び悩んでいる」等。**理由**: 現状FAQが初心者専用になっている。**効果**: 中級者以上のユーザーにもサイトの価値を感じてもらえる
6. **players.htmlの情報量の再整理**: ピックアップ行を折りたたみ式にする等。**理由**: スクロール量が多い。**効果**: 目的の選手に早くたどり着ける

### 優先度: 低

7. **大会情報の運用方針の明確化**: 実データが揃うまでUIの拡張は後回しにする。**理由**: 空のデータ構造を先に作り込むことの効果は限定的。**効果**: 開発リソースをより効果の高い箇所に集中できる

## ■Phase4で実装すべき内容

- CSS構造の分割整理(`components-v2.css`の責務分離)
- 動画カード・軸ラベル辞書など、重複コードの共通化
- 既存ページ(player.css/character関連)のデザインシステムへの追従
- 静的コンテンツ(図鑑・ランキング)への「今日/今週」という時間軸の導入検討

## ■あなたならどう改善するか(自由提案)

- **「毎日の理由」を機能ではなくコンテンツ運用で作る**: 新機能を追加するより、**既存データ(character-data.js等)を使った「今日は○○の対策キャラを紹介」のような軽量なローテーション表示**の方が、開発コストを抑えつつ毎日の変化を作れます
- **上級者向けは「機能」より「見せ方」から着手**: フレームデータのような重い機能実装の前に、既存の`achievements`データを時系列で見せる「大会実績年表」のような**軽量な見せ方の工夫**で上級者の関心を引けないか検討する価値があります
- **Phase4の前に「デザイン負債」の棚卸しを推奨**: 新機能を増やす前に、Phase1で作ったDesign Systemを**既存ページ全体に一度適用し直す「リファクタリングフェーズ」**を挟むことを提案します。今のまま新機能を積み重ねると、デザインの不統一が拡大し続けるリスクがあります

## ■現時点での完成度: 68点 / 100点

**内訳の考え方**: 初心者体験の設計(診断・導線・ガイド)は高水準(90点相当)である一方、中級者・上級者への価値提供(30点相当)とサイト全体のデザイン統一性(60点相当)が全体の点数を押し下げています。「初心者向けサービス」としては非常に高い完成度ですが、「SF6総合ポータルサイト」を名乗るには、**中〜上級者への価値提供とコンテンツの継続的な鮮度**という2つの宿題が残っている状態です。
