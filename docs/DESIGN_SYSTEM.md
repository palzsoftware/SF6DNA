# SF6DNA Design System

Riot Games風をベースに、eスポーツ大会のライブ感を取り入れたデザインコンセプトを、サイト全体で再利用可能なルールに落とし込んだドキュメントです。**このドキュメントだけを見れば、今後どのページを追加しても統一感を保てること**を目標にしています。

まだコードには反映していません。次フェーズでこの内容をCSS変数として実装します。

---

## Color System

| トークン名 | 値(案) | 用途 |
|---|---|---|
| `--color-brand` | `#ff6b00` | ブランドカラー。SF6DNAを象徴するオレンジ。Primaryボタン、CTA、最重要な強調に使う |
| `--color-brand-hover` | `#ff8d3d` | ブランドカラーのホバー・明るいバリエーション |
| `--color-brand-pressed` | `#cc5500` | ボタン押下時など、暗いバリエーション |
| `--color-accent-cool` | `#3ad6ff` | セカンダリアクセント(寒色)。LIVE表示・ランキング更新・大会情報など「速報性」を示す場面専用 |
| `--color-success` | `#38d996` | 成功・上達・プラスの変化(スコア上昇など) |
| `--color-warning` | `#f5a623` | 注意喚起(データ未整備、期限が近い等)。現状未定義のため新規追加 |
| `--color-danger` | `#ff4b55` | エラー・削除・下降変化(スコア低下など) |
| `--color-bg` | `#0d1117` | ページ全体の背景(既存踏襲) |
| `--color-surface` | `#161b22` | カード等の基本背景(既存踏襲) |
| `--color-surface-elevated` | `#1f2630` | ホバー時・ポップオーバー等、一段明るい背景(既存踏襲) |
| `--color-text-primary` | `#ffffff` | 見出し・本文の主色 |
| `--color-text-secondary` | `#b5bcc8` | 補足テキスト(既存踏襲) |
| `--color-text-muted` | `#6b7280` | プレースホルダー・注釈など最も控えめなテキスト |
| `--color-border` | `#2b3442` | 標準の境界線(既存踏襲) |

**使用ルール**: ブランドカラー(オレンジ)は「1画面に主役級のCTAは1つ」を原則とする。それ以外の強調は`--color-accent-cool`(速報性)、`--color-success`/`--color-danger`(状態変化)で意味を使い分け、色を役割ごとに固定することでサイト全体の一貫性を保つ。

## Typography

| 用途 | フォント | サイズ | ウェイト |
|---|---|---|---|
| 見出し(H1: ページタイトル) | 見出し用ディスプレイフォント(英数字: Rajdhani等の締まった書体、日本語: Noto Sans JP) | 28-34px | Bold |
| 見出し(H2: セクション) | 同上 | 20-24px | Bold |
| 見出し(H3: カードタイトル内の小見出し) | 同上 | 16-18px | Medium |
| 本文 | Noto Sans JP / Segoe UI(既存踏襲) | 14-15px | Regular |
| ラベル・タグ・バッジ | 同上 | 11-12px | Medium、letter-spacing 0.05〜0.08em |
| 数値(スコア・XP・MR等) | 等幅系フォント(Roboto Mono等) | 用途に応じて16-28px | Medium〜Bold |
| カードタイトル | 見出し用ディスプレイフォント | 15-16px | Medium |

**使用ルール**: 「見出し用ディスプレイフォント」は英数字部分にのみ効果的に使う(タクティカルな締まった印象を出すため)。日本語文字列に対して同じフォントを強制すると可読性が落ちるため、日本語部分は引き続きNoto Sans JPを使用する。数値専用に等幅フォントを充てることで、スコアボードのような緊張感を演出する。

## Spacing

4pxを基準とした8段階のスケールで統一する(現状、余白トークンが存在せずページごとにバラバラだった課題への対応)。

| トークン名 | 値 | 主な用途 |
|---|---|---|
| `--space-xs` | 4px | アイコンとテキストの間隔など最小単位 |
| `--space-sm` | 8px | バッジ内側の余白、カード内の要素間 |
| `--space-md` | 12px | カード間のgap |
| `--space-lg` | 16px | カード内部のpadding標準値 |
| `--space-xl` | 24px | セクション内の見出しと本文の間隔 |
| `--space-2xl` | 32px | セクション間のmargin(デスクトップ) |
| `--space-3xl` | 48px | 大きな区切り(ホームの主要ブロック間など) |
| `--space-4xl` | 64px | ヒーローセクションの上下padding |

**Paddingのルール**: 通常カード = `--space-lg`、ヒーローカード = `--space-2xl`〜`--space-4xl`、ボタン = 縦10px・横20px固定。
**Marginのルール**: セクション間は`--space-2xl`(デスクトップ)/`--space-xl`(モバイル)に統一する。

## Border

### クリップ形状(ブランドの世界観を作る核となる要素)

角丸ではなく、1辺の角を斜めにカットする形状をブランドの視覚的シグネチャーとする。**カット幅はコンポーネントの重要度で固定値を使い分ける**(%指定にすると要素サイズごとにカットの印象がバラつくため)。

| 用途 | カット幅 |
|---|---|
| ヒーローカード | 24px |
| 通常のフィーチャーカード(Character Card / Player Card / Video Card等) | 16px |
| ボタン(Primary) | 8px |

```
clip-path: polygon(0 0, 100% 0, 100% calc(100% - {カット幅}), calc(100% - {カット幅}) 100%, 0 100%);
```

### 通常カード

一覧の行(履歴一覧、ランキングリストなど密度の高いリスト)には、クリップ形状は使わず`border-radius: 8px`のシンプルな角丸を使う。**「主役級のカードだけクリップ形状、リスト系は角丸」という使い分けを徹底することで、クリップ形状の乱用による視覚疲労を防ぐ。**

### ボタン

Primaryボタンのみクリップ形状(8px)。Secondary/Ghostボタンは`border-radius: 4px`の通常の角丸とし、視覚的な優先度の差をここでも表現する。

## Shadow

ダークテーマ主体のため、ぼかしのある影(box-shadow)は控えめに使う方針とする。

| 状態 | 指定 |
|---|---|
| 通常 | 影なし。`border: 0.5px solid var(--color-border)`のみで境界を示す |
| Hover | 影ではなく、境界線の色を`--color-brand`に変化させ、背景を`--color-surface-elevated`に一段明るくする |
| Hero | 影ではなく、背景の面(サーフェス)を重ねることで奥行きを表現する(グラデーションは使わない) |
| ドロップダウン/ポップオーバー(唯一shadowを使う場面) | `box-shadow: 0 8px 24px rgba(0,0,0,0.4)` |

## Animation

ゲームサービスとしての「気持ちよさ」を演出するため、単なる装飾ではなく**フィードバックとしてのモーション**を設計する。

### 基本トークン

| トークン名 | 値 | 用途 |
|---|---|---|
| `--duration-fast` | 120ms | ホバー、色の変化 |
| `--duration-base` | 200ms | フェード、通常の状態変化 |
| `--duration-slow` | 400ms | スライド、達成演出 |
| `--ease-standard` | cubic-bezier(0.4,0,0.2,1) | 通常の動き |
| `--ease-overshoot` | cubic-bezier(0.34,1.56,0.64,1) | 達成演出(跳ねるような気持ちよさを出す) |

### 場面別のモーション定義

| 場面 | モーション |
|---|---|
| Hover | 境界線色が`--duration-fast`で変化、ボタンはわずかに拡大(scale 1.0→1.02) |
| Click | ボタンが`scale(0.97)`に縮み、離すと戻る(押した感触の演出) |
| Fade | コンテンツ出現時、opacity 0→1を`--duration-base`で |
| Slide | カードがビューポートに入る際、`translateY(8px)`からフェードしながら定位置へ(`--duration-base`) |
| Progress | スコアバー・XPバーは、幅(または長さ)が`--duration-slow`かけて`--ease-standard`で伸びる |
| XP演出 | 数値はカウントアップ(0から目標値まで`--duration-slow`)、バーの伸びと同期させる |
| 診断完了 | 結果カードが`--ease-overshoot`でわずかに拡大しながら出現、直後に8軸スコアバーが上から順に少しずつ遅延して伸びる(stagger) |
| 練習完了 | 完了ボタン押下でチェックアイコンが`--ease-overshoot`で出現、連続日数カウンターがパルス(一瞬拡大→戻る) |
| バッジ解除 | バッジアイコンが`scale(0)→scale(1.1)→scale(1)`の順で`--ease-overshoot`により出現(発光やパーティクルではなく、動きそのもので達成感を作る) |
| カード表示(グリッド) | グリッド内のカードが左上から順に`--duration-fast`ずつ遅延してフェード+スライドイン(5件以上は遅延を打ち切り、体感速度を優先) |
| ページ遷移 | リンク押下時にコンテンツがわずかにフェードアウトしてから遷移、新ページ読み込み時はフェードインする |

**使用ルール**: モーションは「意味のあるフィードバック」としてのみ使う。装飾目的だけの常時アニメーション(常時点滅するバッジ等)は禁止とする。

## Icon System

| 項目 | ルール |
|---|---|
| ライブラリ | Tabler Icons(アウトライン)に統一。絵文字は使用しない |
| サイズ | インライン(テキスト内)16px / 標準(ボタン・ナビ)20px / 装飾(featureグリッド等)24px |
| 線幅 | 全アイコンで統一(Tablerのデフォルトのアウトライン幅をそのまま使用し、太さを混在させない) |
| 色 | 基本はテキスト色を継承。状態を示す場合のみ`--color-success`/`--color-danger`等を使う |
| 利用ルール | アイコン単体での使用は避け、原則テキストラベルと併用する。アイコンのみのボタンには`aria-label`を必須とする |

## Card Component

### Hero Card
- **用途**: ページの主役情報(診断結果、キャラクター名、プレイヤー名など)を1つだけ提示する
- **使用ルール**: 1ページに1つまで。クリップ幅24px、padding `--space-2xl`以上
- **使用例**: 診断結果ページ最上部、キャラクター/プレイヤー詳細のヒーロー部分
- **してはいけない例**: 一覧ページで複数のHero Cardを並べる、通知やエラーメッセージにHero Cardを流用する

### Metric Card
- **用途**: 単一の数値+ラベルを見せる(スコア、実績数、MRなど)
- **使用ルール**: 2〜4枚のグリッドで使用。長文やボタンを内包しない
- **使用例**: 8軸スコア、実績数(Top8実績・格ゲー歴等)
- **してはいけない例**: 説明文を長々と書く、画像を主役にした内容に使う(Video Card等を使う)

### Video Card
- **用途**: 動画サムネイルとタイトルの提示
- **使用ルール**: 常に16:9のアスペクト比を維持。再生アイコンのプレースホルダーを必須とする
- **使用例**: コンボ動画一覧、おすすめ動画
- **してはいけない例**: アスペクト比を崩す、複数の動画情報を1枚に詰め込む

### Character Card
- **用途**: キャラクターの一覧・選択画面での表示
- **使用ルール**: アイコン/アート+名前+タイプタグのみに情報を絞る。詳細説明は入れない
- **使用例**: キャラクター一覧グリッド、診断結果のおすすめキャラクター
- **してはいけない例**: カード内に長い特徴説明文を入れる(詳細ページに誘導する)

### Player Card
- **用途**: 選手の一覧・紹介での表示
- **使用ルール**: アバター+名前+所属+代表的な1指標を必須とする(トレーディングカードらしさを担保)
- **使用例**: プレイヤー一覧、診断結果の参考選手
- **してはいけない例**: 所属チーム情報を省略する、選手以外(キャラクター等)に流用する

### Training Card
- **用途**: 練習ドリルの詳細提示。6種の中で唯一、情報量の多いカード
- **使用ルール**: 理由・目的・手順・目標・難易度バッジ・完了アクションを省略しない
- **使用例**: 練習メニュー画面のドリル一覧
- **してはいけない例**: 手順を1つの段落文に圧縮する、完了アクションを省略する

## Button

| 種別 | スタイル | 用途 | 使用ルール |
|---|---|---|---|
| Primary | `--color-brand`背景、クリップ形状(8px)、濃色テキスト | そのページで最も重要な1アクション | 1画面に原則1つまで表示する |
| Secondary | 透明背景+`--color-border`の境界線、通常の角丸(4px) | 補助的なアクション | Primaryと並べる場合は視覚的な主張を弱く保つ |
| Danger | `--color-danger`の境界線または背景 | 削除・取り消しなど破壊的な操作 | 誤操作防止のため、確認なしに実行される操作には使わない |
| Ghost | 背景・境界線なし、テキスト+アイコンのみ | ナビゲーションリンク、「もっと見る」等の軽い操作 | 重要なアクションには使わない(視認性が低いため) |

## Navigation

### Header
- サイト共通のヘッダーとして全ページ上部に固定表示(既存の高さ測定ロジックを踏襲)
- ロゴ・主要ナビゲーション・表示モード切替を横並びに配置

### Dropdown
- クリック/タップで開閉(ホバー非対応端末への配慮を継続)
- 開いた際は`--color-surface-elevated`背景+ドロップシャドウ(Shadowセクションのポップオーバー仕様)を適用

### Mobile
- 現状のハンバーガー+2階層ドロップダウンは、操作コストの観点から将来的に見直しを推奨する(UX_REVIEW.mdの指摘を踏襲)
- 具体的には、診断・図鑑・ランキング・マイページ等の主要項目をボトムタブ化し、About等の副次的な項目のみハンバーガーに残す構成を将来案として提示する(**この項目は本デザインシステムの範囲を超えた構造変更のため、別途実装フェーズで判断する**)

## このデザインシステムの使い方

新しいページ・新しい機能を追加する際は、以下の順で本ドキュメントを参照する。

1. その画面の主役情報は何か → Hero Cardの要否を判断
2. 提示する情報の種類 → Metric/Video/Character/Player/Training、いずれのCard Componentに当てはまるか
3. 色は役割で選ぶ(ブランド/速報性/成功/警告/エラー)。装飾目的で色を増やさない
4. 余白はSpacingスケールの値のみを使う。中間的な半端な数値を新設しない
5. アクションボタンはPrimary/Secondary/Danger/Ghostのいずれかに必ず当てはめる
6. 動きを追加する場合は、Animationセクションの「場面別モーション定義」に当てはまるものを流用し、新しいモーションパターンを安易に増やさない
